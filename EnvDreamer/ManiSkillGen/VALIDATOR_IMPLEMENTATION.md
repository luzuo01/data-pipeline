# SceneGenerator + Validator 第一阶段交付

日期：2026-10-26。本次实现在独立的 `ManiSkillGen` 模块中；不依赖 EnvDreamer-20k，不训练分类器，不包含 TrajectoryGen。

本文记录场景验证阶段的范围。后续已新增 TrajectoryGen 和 GTExporter，见 [三模块实现说明](PIPELINE_IMPLEMENTATION.md)；表中的“完整任务执行未测试”指单独的场景预检，完整数据管线会另外执行任务并保存成功验证结果。

## 已实现的闭环

自然语言 / SceneSpec → 规范化 → 一次随机化 → 结构化验证 → 有限位置修复 → 重新验证 → 真实环境初始化 → 短时仿真检查 → 必要时重新布置并重建环境 → 通过后保存预览和审计。

所有修复共享 `max_repair_attempts` 上限，默认 3，最多 5。静态修复每轮每个问题物体最多尝试 97 个位置；运行时失败后每轮最多尝试 64 个候选场景。不能通过则停止，失败不会覆盖已接受的截图。位置采样由 seed 决定。

报告中 `true`=通过、`false`=失败、`null`=未测试。`ok=true` 只表示已实现的检查没有失败，不是任意操作可完成性的证明。库级软件预览仍可用于离线检查，物理检查为 `not_tested`；网页强制真实运行时。

ManiSkill 阈值：最终 5 个样本线速度 ≤0.03 m/s、角速度 ≤0.3 rad/s；相对初始化位移 ≤0.05 m；桌面/工作空间运行时余量 5 mm；接触穿透 ≤5 mm；最终机器人最大关节速度 ≤0.5。短窗口不能替代长时间稳定性或可操作性验证。包围盒可能保守拒绝曲面靠近场景。

PORTAL 阈值：最终 5 个样本活跃自由度的最大广义速度 ≤0.5，最终接触穿透 ≤1 cm。平移和旋转自由度使用同一粗略数值阈值，报告仅用于初始化预检。NutAssembly 的单物体模式会由 robosuite 将未启用的螺母移到 `(10,10,10)`；该螺母继续自由落体。验证器依据基准的 `single_object_mode` 和 `obj_to_use` 排除其速度，并在报告列出名字；所有状态仍检查有限性，不修改仿真物体来掩盖错误。

## 修复与意图约束

- 只修改未锁定物体的 `pose`。不删除物体，不改资产、尺寸、颜色、任务、成功阈值或工作空间。
- 位置随机化先执行一次；修复重试不重新随机化颜色和任务。锁定物体不进行位置随机化。
- `repair.locked_object_ids` 锁定指定对象；`repair.allow_pose_changes=false` 锁定全部位置。
- 无法识别的 `constraints`、未支持的旋转/物理属性、自定义 PORTAL 布局等返回错误，不能默默忽略。
- 模型输出无效场景时保留供验证/修复；不会替换成默认任务。模型请求失败/缺少 key 时仍允许有明确来源标记的本地模板。
- 自然语言的任意语义约束尚不能自动证明；精确位置应使用 JSON 锁定。本地左右位置解析会锁定相应物体，模型提示也要求固定位置输出锁定字段。

## 代码入口

- `validation_rules.py`：稳定错误码、对象/字段定位、可修复性、静态检查。
- `repair.py`：确定性静态修复和运行时失败后的候选位置采样。
- `runtime_validation.py`：ManiSkill 静置、状态和接触检查。
- `generator.py`：总重试预算、真实渲染门禁、审计、环境资源管理。
- `portal_trace_worker.py`：独立 MuJoCo 检查、状态导出、真正设置 robosuite seed。
- `app.py` / `templates/index.html`：验证、修复、生成接口；生成串行运行于同一线程；网页状态与已接受截图一致。

附带修正：Panda 初始化为 rest 姿态并设置实际保持目标；圆柱的局部 X 轴旋转为世界 Z 轴；任务成功判定区分放置/推动与堆叠，检查目标足迹、高度、静止和释放；默认相机调整为斜上方，直接使用 SceneSpec 相机外参，停止静默改写相机位置。

## 使用与验证

```powershell
cd F:\PKU\DATA_PIPELINE\EnvDreamer
& D:\APP\Anaconda\python.exe -m ManiSkillGen --port 8765
```

浏览器访问 `http://127.0.0.1:8765/`。当前 Windows TCP 保留段包含 8090（8011–8110），因此本机使用 8765 或其他空闲端口。代码修改后需重启服务。

展开网页“直接使用 SceneSpec JSON”：

1. 粘贴 `examples/repairable_scene.json`，应把越界悬空方块移回桌面，通过仿真，修复记录显示前后坐标。
2. 粘贴 `examples/locked_invalid_scene.json`，应失败且不移动锁定对象。
3. 关闭自动修复再使用第一个场景，应直接失败。

`POST /api/maniskill/scene/validate` 为只读静态验证；`POST /api/maniskill/scene/repair` 为离线静态修复；`POST /api/maniskill/scene/generate` 执行完整链路。

生成参数：`spec` 或 `prompt`、`seed`、`render`、`auto_repair`、`max_repair_attempts`。当前仅支持 `num_envs=1`。`outputs/manifests` 保存成功规范、原始规范、随机化后规范、逐次问题与补丁、最终运行时状态；失败保存为 `failed_*.json`。一个 generator 只保留最新环境，成功生成下一个后关闭前一个；调用者结束使用后负责关闭最新 `instance['env']`。

```powershell
& D:\APP\Anaconda\python.exe -m pytest ManiSkillGen/tests -q
```

自动测试结果：**41 passed**。

验收包括：坏输入/NaN、碰撞、悬空、marker 支撑、语义错误、锁定/不可修复情况、确定性与不修改输入、运行时异常、重建和重试上限、截图失败、失败审计与旧预览保留、API 行为。真实运行验证了 ManiSkill 默认场景、圆柱、堆叠、越界悬空修复，以及六个 PORTAL 注册任务的初始化探针（Panda、seed=3；不是全部机器人或随机种子覆盖）。

浏览器验收：1280×720 下页面和默认侧栏无需纵向滚动；详情区内部滚动。实际点击生成得到“修复 1 次”，记录 `[1,0,1.2] → [0.38,0,0.77]`，随后 20 步仿真通过。截图与真实仿真测试输出保存在 `outputs/validator_smoke/`。

## 下一阶段边界

完整的场景可操作性仍需要无碰撞 IK、抓取候选、路径规划/轻量脚本控制器和任务特定几何检查。PORTAL 任意布局生成与修复需要单独的任务场景适配器，目前只支持注册场景。以上内容不是本阶段已经完成的功能，也不应因几何检查通过而推断成功。
