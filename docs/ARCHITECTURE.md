# 架构与工作范围

## 目标

把自然语言机器人任务转为可检查的场景、成功执行轨迹、可追溯训练数据和白模可视化。输入可以是自然语言，也可以是完整 `scene_spec_v1` JSON；JSON 用于确定性验收。

## 主链路

1. **任务解析**：`planner.py` 输出 SceneSpec，包括机器人、物体、相机、任务模板、成功条件、随机化设置。模型只返回 JSON；无 key 或调用失败的本地回退会记录来源。
2. **验证与修复**：`validator.py`、`repair.py`、`runtime_validation.py` 检查结构、几何和短时稳定性。修复只移动未锁定物体，不改变任务、尺寸或成功阈值。
3. **场景编译**：`generator.py`、`maniskill_env.py` 实例化 ManiSkill3 / SAPIEN 场景。正式数据链路禁止软件示意图回退。
4. **轨迹生成**：`kinematics.py`、`trajectory.py` 用 Panda URDF 数值 IK、笛卡尔路点与关节插值产生控制指令，真实执行并检查成功。
5. **同步真值**：`gt_exporter.py` 恢复执行时记录的引擎状态，渲染同一时刻的多相机数据，检查状态恢复、相机重投影、法线、分割和几何相容性，写内部 HDF5。
6. **LeRobot 转换**：`EnvGen/Scripts/lerobot_export.py` 在独立解释器调用 `lerobot_conversion/convert_hdf5.py`，生成标准数据和语义清单，打包 ZIP。
7. **白模回放**：`ue_trajectory_render.py` 将 Panda 与物体状态映射到 UE 的厘米坐标，校核回读位姿，生成 MP4 与回放报告。UE 不决定主链路物理成功。
8. **发布与审计**：`pipeline.py`、`app.py` 管理批次、进度、失败与下载。单个仿真线程串行使用 SAPIEN。

## 成功、失败与完整交付

- `complete`：请求的数据 episode 全部成功。
- `partial`：部分成功；失败项在 `failed_episodes`。
- `failed`：没有成功 episode。
- 白模失败不撤销有效数据；还需检查 `ue_render_error`、视频路径与回放报告。
- 真值表示仿真状态，不证明真实机器人迁移效果。场景验证、轨迹验证、格式验证、视觉质量是不同层次。

## 支持范围

主链路支持 Panda / Franka 的 box 抓取放置、堆叠与推动。被操作 box 的 XY 尺寸不超过 6.5 cm，堆叠支撑为 box；实际使用 `pd_joint_pos`。通用无碰撞规划、机器人自碰撞认证、任意机械臂动作统一、照片级渲染和真实世界保真验证尚未完成。

随机种子产生独立场景并重新执行，但必须配置随机化；没有随机化的重复任务不自动构成几何多样化。

## 实验及补充模块

`backend=ue5` 的 Sawyer / UR5e 代码保留用于后续工作。目前有程序生成轨迹、颜色近似分割、零值深度/法线和单位矩阵相机参数，不能称为完整引擎真值。相关实验机器人资产不随主链路包发布；主链路验收不覆盖这些任务。

PORTAL-Trace 保留任务注册、隔离运行时和场景预览，尚无成功轨迹导出。`data_engine/` 负责既有数据导入，来源适配器与动作语义独立于合成管线。

后续优先事项：补齐 UE 独立渲染帧与像素级对齐、多机器人真实控制器与原生传感器、多任务与种子的成功率统计、数据规模与存储开销评估。
